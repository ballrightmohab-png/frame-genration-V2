## 2025-05-18 - OpenMP collapse vs Row-Invariant Hoisting in 2D Frame Reprojection
**Learning:** OpenMP `#pragma omp parallel for collapse(2)` requires perfectly nested loops with no statements between row (`y`) and column (`x`) iterations. For 1080p+ frame interpolation, hoisting row-invariants (such as row normalized coordinates, row offsets, and row matrix products) out of the inner loop saves over 2,000,000 redundant floating-point calculations per frame. Standard outer-loop OpenMP parallelization over rows (`#pragma omp parallel for`) provides plenty of thread iterations while enabling row hoisting.
**Action:** When parallelizing 2D image/frame reprojection loops, prefer single-level OpenMP row parallelization to allow hoisting row invariants out of the inner pixel loop.
